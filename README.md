# Проект: Управление оборудованием в дата-центре (Стойки, Серверы, Сервисы, Инциденты)

Реляционная база данных для инвентаризации, мониторинга и эксплуатации ИТ-инфраструктуры распределенной сети дата-центров.

## 1. Тема и предметная область

**Тема проекта:** Автоматизация учета физического и сетевого оборудования, развернутых сервисов, персонала и зарегистрированных инцидентов в дата-центрах.

**Основные сущности:**

* **Дата-центры** (`datacenters`): Список площадок с указанием названия, страны, города и физического адреса.
* **Стойки** (`racks`): Размещенные в дата-центрах серверные стойки с ограничениями по высоте (в юнитах) и максимальной потребляемой мощности (кВт).
* **Серверы** (`servers`): Вычислительное оборудование (физические серверы), установленное в стойках, со своими характеристиками (ЦПУ, RAM, объем дисков, ОС, IP-адрес) и текущим статусом.
* **Сетевые устройства** (`network_devices`): Коммутаторы, маршрутизаторы и межсетевые экраны (firewalls), обеспечивающие сетевую связность в стойках.
* **Сервисы** (`services`): Программное обеспечение и сервисы, обслуживаемые ИТ-командами.
* **Сотрудники** (`employees`): Технический персонал (администраторы, инженеры, операторы), обслуживающие инфраструктуру.
* **Инциденты** (`incidents`): Зарегистрированные сбои и аварии с указанием уровня критичности, статуса, затронутого сервиса и серверов, а также назначенных сотрудников для устранения.

**Автоматизированные процессы:**
1. Инвентаризация физического и сетевого оборудования, привязка к стойкам и дата-центрам.
2. Контроль емкости и ограничений стоек (доступные юниты и лимиты мощности).
3. Учет и распределение программных сервисов по серверам.
4. Мониторинг работоспособности серверов и сетевого оборудования (отслеживание статусов `online`, `offline`, `failure`, `active`, `maintenance`).
5. Управление инцидентами: регистрация сбоев, определение степени критичности, назначение ответственных инженеров и контроль сроков решения.

## 2. Структура базы данных

### Файлы проекта:
* [schema.sql] - Создание таблиц, индексов, ограничений целостности и автоматическое наполнение демонстрационными данными (seed data).
* [init.sql] - Демонстрационные данные (seed data) для вставки (на случай раздельной инициализации).
* [queries.sql] - 20 аналитических запросов к базе данных.
* [req.sql] - 20 дополнительных эксплуатационных и аналитических запросов с применением сложных конструкций (CTE, HAVING, LIMIT).
* [docker-compose.yml] и [Dockerfile] - Конфигурация для быстрого развертывания СУБД PostgreSQL в контейнере.
* [image.png] - ER-диаграмма связей между таблицами.

### Ключевые таблицы:

| Таблица | Описание | Первичный ключ (PK) | Внешние ключи (FK) |
| --- | --- | --- | --- |
| **datacenters** | Список дата-центров | `id` | - |
| **racks** | Стойки в дата-центрах | `id` | `datacenter_id` (ссылается на `datacenters.id`) |
| **servers** | Вычислительное оборудование (серверы) | `id` | `rack_id` (ссылается на `racks.id`) |
| **network_devices** | Сетевое оборудование (коммутаторы, роутеры) | `id` | `rack_id` (ссылается на `racks.id`) |
| **services** | Программные ИТ-сервисы | `id` | - |
| **server_services** | Таблица связи серверов и развернутых сервисов | `(server_id, service_id)` | `server_id` (на `servers`), `service_id` (на `services`) |
| **employees** | Обслуживающий персонал | `id` | - |
| **incidents** | Журнал зарегистрированных инцидентов | `id` | `affected_service_id` (ссылается на `services.id`) |
| **incident_servers** | Серверы, затронутые конкретным инцидентом | `(incident_id, server_id)` | `incident_id` (на `incidents`), `server_id` (на `servers`) |
| **incident_assignments** | Назначение сотрудников на решение инцидентов | `(incident_id, employee_id)` | `incident_id` (на `incidents`), `employee_id` (на `employees`) |

### Ограничения целостности (Constraints):
* **`NOT NULL`**: Имена дата-центров, коды стоек, IP-адреса, роли сотрудников, почта, уровни критичности инцидентов.
* **`UNIQUE`**: Коды стоек (`racks.code`), IP-адреса серверов и сетевых устройств, адреса почты сотрудников (`employees.email`), названия ИТ-сервисов (`services.name`).
* **`CHECK` ограничения:**
  * Состояние серверной стойки: `status IN ('active', 'maintenance', 'offline')`
  * Статус сервера: `status IN ('online', 'offline', 'failure')`
  * Тип сетевого оборудования: `type IN ('switch', 'router', 'firewall')`
  * Статус сетевого устройства: `status IN ('active', 'offline', 'maintenance')`
  * Роль сотрудника: `role IN ('admin', 'engineer', 'operator')`
  * Статус инцидента: `status IN ('open', 'in_progress', 'resolved')`
  * Уровень серьезности инцидента: `severity IN ('low', 'medium', 'high', 'critical')`

### Индексы для оптимизации:
* `idx_servers_rack` на `servers(rack_id)` - ускоряет поиск серверов в конкретной стойке.
* `idx_servers_ip` на `servers(ip_address)` - быстрый поиск по IP-адресу.
* `idx_incidents_status` на `incidents(status)` - ускорение фильтрации активных/закрытых инцидентов.
* `idx_incidents_severity` на `incidents(severity)` - ускорение выборки критичных аварий.
* `idx_services_name` на `services(name)` - быстрый поиск по названию ИТ-сервиса.

## 3. Контейнеризация и быстрый запуск

Для удобства локального запуска база данных PostgreSQL разворачивается через **Docker**.

### Конфигурация подключения:
* **Хост:** `localhost` (или `127.0.0.1`)
* **Порт на хосте:** `5434` (перенаправляется на `5432` в контейнере)
* **Имя базы данных:** `servers_database`
* **Пользователь:** `servers_user`
* **Пароль:** `servers_password`

### Шаги для запуска:

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/KBACokk/Db_local
   cd Db_local
   ```

2. Запустите контейнер с базой данных в фоновом режиме:
   ```bash
   docker compose up -d
   ```
   *При первом запуске автоматически выполнится скрипт `schema.sql`, который создаст все необходимые таблицы, индексы и наполнит базу данных 30 дата-центрами, 100+ стойками, 300 серверами, сетевым оборудованием, сотрудниками и тестовыми инцидентами.*

3. Проверить статус контейнера:
   ```bash
   docker compose ps
   ```

4. Для подключения к базе данных из терминала используйте:
   ```bash
   docker exec -it servers_db psql -U servers_user -d servers_database
   ```
   Или подключитесь с помощью любого графического клиента (DBeaver, pgAdmin, DataGrip), используя параметры подключения выше.

5. Остановить и удалить контейнер:
   ```bash
   docker compose down -v
   ```
